**推翻第一轮的「表冠 = F1/F2」推测**：表冠旋转芯片（pixart PAT9125）上报 `REL_WHEEL` 相对滚轮事件，F1 是侧边功能键。App 层监听 REL_WHEEL 需读输入设备或 `dispatchKeyEvent` 之外的方式（Android 无标准 REL_WHEEL API，需 `InputDevice` 扫描或 native 读 /dev/input）——「表冠当物理旋钮」玩法技术上可行但工程量比按键大。

## 3 亮屏门控（本轮最重要的新发现）

**灭屏时所有传感器对第三方零回调；亮屏后立即恢复高速出数。** 证据链：

1. 11:40（灭屏）：19 传感器注册成功（dumpsys 确认 15+ 条注册行、`status: active`、`samplingPeriod=2000us`），15 秒统计**零回调**
2. 11:44（KEYCODE_WAKEUP 亮屏后）：同一 App（pid 6637）瞬间出现 `#2000 心跳` 数据流——12 路 PPG + ECG_RAW 全在出数
3. 11:47（冷启动重装 + 亮屏）：15 秒统计 14 个传感器全活跃（上表）
4. 反向验证：屏幕再灭 → App 进程被杀（`pidof` 空）→ 数据流停

**对产品的含义**：
- 「宠物 App」必须亮屏才能采健康数据（与 ROM 省电策略一致，符合预期——手表本来就是亮屏交互设备）
- 灭屏即杀进程：宠物 App 常驻须走前台服务（AGENT.md §1 硬约束的实证）
- 带 BODY_SENSORS 权限的成品传感器（血氧/心率/ECG 成品）在本轮**始终零回调**——注意它们是 on-change 型且**灭屏时 HAL 根本不启动测量**；亮屏 + 离座 + 接触皮肤下是否出数，需 Wi-Fi 模式手持复测（本轮停靠位无法区分「未接触皮肤故无新值」与「不喂第三方」）
